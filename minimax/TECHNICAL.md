# 技术说明

## 工作流

`任务与工程 → seekdb 导入/检索 → 当前规格、代码、测试与 PowerContext 进度 → MiniMax 代码修改 → 相同测试前后对比 → PowerContext 保存结果`

业务工程是一个可直接运行 pytest 的任务筛选库。目标缺陷为截止日期比较未包含边界当天，
既有状态筛选、排序、限制、校验和输入不变性需要保持。只有业务源码允许由 MiniMax 改写。

## 分工与来源

- `Corpus` 将资料的路径、种类、SHA-256 和完整正文存入 seekdb；参数化 SQL 根据任务词项评分，
  分别选择规格、代码、测试。上下文使用 SQL 返回值，所有引用均能定位原始文件与行号。
- 重导入使用一个事务替换当前项目索引，避免规格已更新而查询仍用旧内容；其他项目不受影响。
- PowerContext `ScopedMemoryApplication` 保存进度为可修订 Memory；通过公开 Runtime、Scope、
  `remember`、`revise`、`list` API 读写，不自行伪造 PowerContext 数据文件。
- 模块重启后读取已有 Memory，将 `done`、`todo` 和 `validation` 填入开发上下文，待办也据此恢复。
- MiniMax 接收真实上下文并返回限定文件的最终源码。记录任务、提示、最终代码、模型标识和用量，
  不记录鉴权头或模型私有思考文本。代码写入独立副本，测试不允许变化。

## 复现与验收

`run_demo.py` 从新目录开始生成全部初始数据，先运行目标测试和回归测试，再导入资料、更新规格、
存储并跨进程恢复任务状态。真实调用完成后，保存前后代码、统一差异和测试命令、退出码及文件摘要。
评审可用保存的实际 MiniMax 输出重放修改，不依赖 Key，不要求模型重复采样产生同一补丁。
报告逐项显示六个官方条件。没有实际模型记录时，准备过程返回 pending，不能报整体通过。

状态使用 PowerContext 的 SQLite 后端；工程资料始终使用真实 seekdb。两者为不同职责，没有用
SQLite 模拟 seekdb。数据量小，采用词项 SQL 检索即可验证本题的上下文管理流程，无需额外 embedding 服务。
